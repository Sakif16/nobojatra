# NoboJatra fix plan for a demo showcase

**Updated:** 1 October 2026

**Scope:** a credible, usable demo of the existing app. There is no production launch or paid pilot planned.

This is the working checklist. The longer [project assessment](PROJECT_ASSESSMENT_AND_EXPANSION_ROADMAP.md) and Git history contain the original evidence and detailed proposals. IDs in parentheses point back to that assessment. A checked item reflects current source or a recorded decision; it does not certify the deployed site.

## What the demo should promise

NoboJatra lets a signed-in visitor explore car-based route suggestions, compare **estimated** fares and travel times, save plans, and keep the trips they repeat. There are no alerts: the app does not watch a trip for weather, traffic, or fare changes. Notifications only confirm what the visitor did, such as saving a plan. Weather, traffic, place search, cameras, and photo search depend on external services. A saved option is **not a booking**. The ranking is labelled AI route ranking and scores options by fixed rules on time, cost, and comfort. Live traffic is unavailable in Bangladesh with the current provider.

The demo is ready when the core journey works in a browser on the demo host, the UI says what is actually measured or estimated, and a provider failure leaves a clear explanation.

## 1. Fix before sharing the demo

- [x] **Stop cross-user route-cache leakage.** Cache route geometry and metrics without user labels; attach each request's own labels after a hit. Apply the route limit to cache hits too. A focused synthetic test covers two users with matching coordinates and different labels. Deployed behavior still needs browser verification. (G30)
- [x] **Make scheduled times unambiguous.** The form sends a wall-clock time; the server converts it in the origin's time zone and stores an instant and zone. Schedules, summaries, history filters, month groups, and peak-hour checks all read in the trip's zone, whatever zone the server or browser is in. Tests cover Bangladesh, both UK daylight-saving changes, and New York and Los Angeles, each under three process time zones. Five stored schedules were repaired with `scripts/fix-scheduled-times.mts`; one from 17 August fits both readings and was left as stored. The zone lookup is too coarse at borders to reject foreign cities, so that part of G17 stays open. Deployed behavior still needs browser verification, and the host should set `TZ=UTC`. (G04, G36, R09, G17)
- [x] **Correct the product language everywhere.** “Confirm”, “booked”, and “confirmed ride” are now saved-plan wording on the buttons, summary, history, scheduled trips, and notifications, and each screen says a saved plan is not a booking. Fare and ranking screens state that fare bands are estimates, not provider quotes, and that distance and time come from a car route. History totals are labelled as estimates. A test blocks the old phrases from returning. Decisions: the “AI route ranking” label stays, with copy that says what is scored, and “Live traffic” links keep their name. Screens still need a read-through in the browser. (G05, G07, G11, G12, G22, G34, R30, P14)
- [x] **Handle Bangladesh traffic as unavailable.** Countries carry a live-traffic flag, off for Bangladesh. There the app makes no traffic request, hides the map overlay and legend, and shows no delay numbers. Routes, fares, ranking, saved plans, and saved trips each say live traffic is not available. A missing reading is no longer scored as low congestion: ranking applies no traffic adjustment and labels risk as weather-only or not assessed. Peak-hour pricing still applies, since it comes from the clock. Tests cover each of these. Deployed behavior still needs browser verification. (G07, G12)
- [x] **Keep planner inputs and results together.** Place searches and route searches are cancelled when a newer one replaces them, and a late answer is ignored. Editing a place, stop, passenger count, or departure clears the results made for the old inputs. Switching country resets the planner. Route choices are stored in click order, and choosing a different route drops the vehicle saved on the old one, with a message to choose again. Tests cover the vehicle reset and search cancellation; rapid typing, repeated Plan Again clicks, and country switching still need checking by hand in a browser. (G06, G25, R01)
- [x] **Reject a saved-trip vehicle from another country.** No longer applies. Saved trips carried a vehicle only for fare alerts; with the alert system removed (see section 2) a saved trip holds no vehicle, so there is nothing to check. (G18, R27)
- [x] **Close the easy request failures.** API routes read their body through one helper that answers `null`, arrays, and other non-object JSON with a 400. Stops that are not a list are refused. The traffic endpoint takes at most eight points between the ends, which is a full sampled route, and the tile proxy only accepts tiles that exist at their zoom. Tests cover each. (G19, G20)
- [x] **Protect public provider calls for a shared demo.** Place search, reverse geocoding, the tile proxy, and trip validation now need a session. Limits are per account, since an IP address can be claimed in a header. Geocoding has a timeout and a ten-minute cache for repeated queries. Every provider call is counted against a daily budget stored in the database, with defaults in `lib/provider-budget.ts` that should be checked against the plans in use. (G02, G19, G38, P09)
- [x] **Make the local and CI checks green.** `pnpm test` runs 62 tests with no network or database, and CI runs it between lint and build. Inter is bundled in `app/fonts` with its licence, so the build makes no Google Fonts request. A frozen install, type-check, lint, tests, and a clean build pass locally; the CI run itself has not been observed yet. (P08, P10, P14)
- [x] **Check dependencies and basic app security.** Next.js is on 16.3.8 and production dependencies went from 27 advisories to one: a moderate `sprintf-js` issue with no fixed release, reached only through TensorFlow.js's command-line tool, which the app never runs. That one is accepted and listed with its reason in `pnpm-workspace.yaml`, so `pnpm audit --prod` now reports only new findings. Development-only tools are down to one: a high-severity `braces` issue with no fixed release, reached only through the lint plugin. It is accepted and listed with its reason in the same file. The output is in `docs/audits/2026-10-10/`. Basic security headers are set, plus a content security policy with a per-request nonce: scripts run only if the server issued them, and map tiles, the photo model, and the embedded cameras are each allowed for their one purpose. It was checked page by page in a headless browser, signed in and out; it has not been checked on the deployed site. Every API route except sign-in, and every private page, checks for a session, and a test fails if one is added without it. Leaked key: history is left as it is, since the key is recorded as revoked; the revocation itself still needs confirming in the provider's dashboard. (G03, C04, C08)

## 2. Fix for the features actually shown

### Routes, fares, and ranking

- [x] Preserve distinct route shapes even when rounded distance and time match. A regression test covers distinct and near-identical paths. (G13)
- [x] A route search the provider refuses only because it is too long for alternatives is asked for again as a single route; no other failure is retried. Trips are validated along the whole itinerary, so A → B → A is accepted when a stop takes it somewhere, and two identical places in a row are refused. Tests cover both, and one real request confirmed the provider routes a round trip. The single route shows the existing "Only one distinct route found." note; it does not say why. (G14)
- [x] Fare cards, ranked cards, and the saved-plan summary each show the fare's source, and say so when the rate card is standing in for a failed live lookup. A saved plan now stores its source. The fare-alert comparison this item also covered went with the alert system. Tests cover each. Decision: the Pathao source keeps its current name and wording. (G10, G11, G16)
- [x] A "Best for" tag and the cheapest, dearest, fastest, and most-comfortable chips are now true comparisons: an option gets one only when it leads that measure and another option is worse on it, so a lone option gets none, no score, and a note that there is nothing to rank it against. The screen states the ranking rule and which of weather and traffic was unknown and left out. No weather claim is made without a reading. Vehicle times are labelled as estimates. Tests cover each. (G08, G12, G34)
- [x] A trip leaving now uses the current reading; a scheduled trip uses the 3-hour forecast nearest its departure, from the same provider. Screens and saved plans label which one it is. By decision a forecast only informs: it changes no fare and removes no vehicle, though it still counts toward the ranking's small risk deduction. The scheduling window is 5 days, matching the forecast's reach. The severity rule is unchanged and its limits are stated next to the score, including that heavy rain alone rates as moderate. Tests cover each, and one real request confirmed both readings. (G09)
- [x] Each route records how far its origin, stops, and destination pins are from where it meets the road, using the routing response already returned. A gap over 75 m shows a note in the planner results that the pin may not be a usable pickup point or entrance. A place with no drivable road nearby is now named in the error. No walking time is added and no entrance is guessed. Tests cover each, and real requests confirmed both cases. The note appears in the planner only, not on the fares page or saved plan. (G35)

### Saved trips, notifications, and history

- [x] **The alert system is removed.** Decision: the demo does not watch trips. The evaluator, its endpoint, alert conditions, “Check now”, pause and resume, and the fare baseline are gone, so nothing implies background monitoring. The bell, the notification list, and the “Your plan is saved” notification stay. A saved trip is now a bookmark of places and party size with a “Plan this trip” button that opens the planner filled in; saving one makes no provider call. Stored condition and baseline fields are left in the database and are not read. Tests cover the bookmark, older records, and the notification shape. (G15, G16, G18, G31, G33, G37, P05)
- [x] History lists are capped and say when they are cut off: the latest 100 saved plans, 50 searches for the last 7 days, and 200 across the last 6 months. They no longer load route geometry, and two indexes serve their queries. Trip History has separate “Saved plans” and “Route searches” tabs, searches are counted as searches, and a search is no longer stamped as completed. A saved trip that lands over the 20-per-country limit in a simultaneous save is undone, and an edit from a stale copy is refused. Tests cover each. The old one-name-per-account saved-trip index was still in the live database and has been dropped, so a name can now be reused across countries. The two new history indexes build when the app next connects; they were not yet present when checked. (G22, G23, R18, R19)
- [x] The notification list has a “Load older notifications” control, and pages by time and id together, so notifications sharing a timestamp are neither skipped nor repeated. The bell’s poll returns the newest notification with the count and reloads the list whenever either changes, not only when the count rises. Deleting a saved trip asks first and reports a failure. Tests cover paging, the poll, and the confirmation. (G32, R29, P04)

### Optional demo experiences

- [ ] Photo search: offer it only for its known Bangladesh landmarks; name those landmarks, show readable match names, retry a failed model load, reject oversized images, and ignore an old prediction when a newer image is chosen. Its model has no documented provenance or measured accuracy, so avoid general recognition claims. (G27, R23)
- [ ] Cameras: identify the page as an external feed, remove unnecessary iframe permissions, and provide an offline or failed-load state. Do not claim the feeds are operated or verified by NoboJatra. (G28)
- [ ] Make the photo and delete dialogs keyboard accessible, keep focus inside while open, restore focus on close, and test a narrow phone viewport and slow device. (G26, R02, R03, R22)

## 3. Finish the interface and setup

- [x] Pages under the main layout have a loading skeleton and an error page with retry, and the app has a last-resort error page and a not-found page. Browser API calls that show their error to the user read replies through one helper, so an HTML error page from the host becomes a readable message; saving or deleting a profile always releases its button. Every list already had an empty state. Tests cover the reader and the presence of each state. (P03, R28)
- [x] Stops keep an id of their own when reordered. The form has a “Swap origin and destination” button. Schedule limits are re-read when the schedule is opened or focused, and a time that has passed is refused on submit. “Use current location” gives up after ten seconds and says whether it timed out, was denied, or failed. Each stop with no place chosen is marked where it is. These are checked by tests on the form’s source; the form itself has not been exercised in a browser. (R04–R08)
- [x] The map has a “Fit route” button and also refits when a stop changes. Markers name their place on hover, tap, and to screen readers. Values put into Leaflet’s marker HTML are escaped. The base map credits only its own provider, the traffic overlay credits TomTom or Mapbox only while it is shown, and OpenStreetMap tiles use the current address. Tests cover the escaping and check the rest in the map’s source; the map has not been checked in a browser. (R10, R11, R13, R14)
- [x] The fares list can be sorted by fare, comfort, or seats. An excluded option says why and what would bring it back, with a link to change the passenger count. Saved trips can be searched by name or place and sorted, show “3 of 20 saved” before the limit is reached, and disable “New trip” at the limit. Tests cover the sorting, the wording, and the search. (R16, R17, R21)
- [x] The navbar carries the five destinations on every signed-in page, with the current one marked, so Scheduled trips is always reachable; the home page’s duplicate link strip is gone. A shared status message announces errors as alerts and progress as status, and is used by the planner and saved trips; profile messages gained the same roles. The plan summary and delete confirmation use the shared buttons, and the summary has a “Copy plan” button. Dialogs were left alone, as decided for the dialog item below. Tests cover the links, the roles, and the copied text. (P01, P06, R24, R25)
- [x] The five framework sample images are deleted, and the footer no longer shows an address or email that nobody supplied. Every page has its own title, and there is a web manifest and a robots file that admits crawlers to the sign-in pages only. Decision: the fixed dark theme is intentional and is now declared to the browser; the light palette stays unoffered, and map tiles keep their provider’s standard light style. Bangladesh treats Friday and Saturday as non-peak, which takes the peak-hour fare adjustment off Saturday trips. Tests cover each. (P02, P12, P14, R12)
- [x] README and environment example describe the reproducible Node 24 / pnpm 11 demo setup, all 16 seeded rates and their migration, account creation/deletion, provider fallbacks, and known limitations. Startup names missing or invalid required settings together, rejects short auth secrets and example placeholders, and reports optional features that are off. Traffic, weather, password reset and photo search show unavailable states; Pathao falls back to labelled rate-card estimates. Server pages, the layout and navbar share request-scoped session/profile reads, including Profile, which displays defaults until its first save. Validation: 142 tests, type-check, lint and a production webpack build pass. The Turbopack build stalled in this environment; authenticated browser and deployed-provider checks remain unverified. (C02, G24, P13, P14)

## Explicit demo limits and deferred work

These are documented limitations, not promises for this project:

- No booking, official fare quote, validated market-wide prices, or guaranteed arrival time. Rate cards and vehicle duration multipliers are illustrative. (G05, G10, G12, G34)
- No live Bangladesh traffic provider, full-country geographic verification, or verified pickup-point catalogue. (G07, G17, G35)
- No alerts or monitoring of a trip, and no notifications outside the browser; no email/push delivery promise. (G15, P05)
- No general-purpose image recognition or owned camera network. (G27, G28)
- No multi-instance cache/queue architecture, commercial billing, fleet telemetry, partner integrations, full privacy operations, or complete Bengali localization. Revisit only if the project scope changes. (G19, G29, P07)
- Feature candidates F01–F24 and R15 are outside this fix checklist. Add one only if it helps the chosen demo story.

## Verification before calling the plan done

1. Run type-check, lint, focused tests, and a clean build. On 1 October 2026, type-check passed, lint had one error, and a local build stopped while fetching Inter in a network-restricted environment.
2. On the demo host, use two separate accounts to check sign-in, country switch, route search, fare comparison, save plan, saved trips, history, and account deletion.
3. Exercise Bangladesh traffic-unavailable, provider timeout, empty results, invalid input, and mobile keyboard navigation.
4. Check the deployed pages and API responses directly. A passing build does not prove the authenticated or provider-backed flow.
5. Convert the old diagnostic scripts under [docs/audits](docs/audits) into tests of the fixed behavior. They currently assert old defects and can stop on stale assumptions.
